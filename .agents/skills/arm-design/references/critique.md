# Design Critique Reference

Use this for visual audits, design review, redlines, and improvement recommendations.

## Critique Principles

- Be specific and evidence-backed.
- Separate observation, interpretation, and recommendation.
- Prioritize fixes by user impact and implementation cost.
- Do not dunk on the work. Diagnose it.

## Review Dimensions

Score only when useful:

- hierarchy
- clarity
- visual coherence
- accessibility
- interaction affordance
- brand fit
- information density
- craft and polish

## Output Structure

```markdown
# Design Critique

## Overall Read

## What Works

## Highest-Impact Issues

| Priority | Issue | Evidence | Fix |
|---|---|---|---|

## Quick Wins

## Deeper Redesign Options

## Risks Or Assumptions
```

## Redline Mode

If screenshots or files are available, inspect them visually. When possible, cite specific screen areas such as header, hero, primary CTA, card grid, nav, chart area, or footer.

## Done When

- The review identifies concrete visual issues.
- Fixes are prioritized.
- Recommendations are actionable.
- Any assumptions are named.
